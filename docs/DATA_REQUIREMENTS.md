# Inputs and data handling

## Prepared model inputs

`matrix` format for iSTAR/scstGCN:

```text
he-raw.tiff
cnts.tsv
locs-raw.tsv
pixel-size-raw.txt
radius-raw.txt
gene-names.txt
```

`visium` format for TESLA/SuperST:

```text
filtered_feature_bc_matrix.h5    (TESLA also accepts feature_bc_matrix.h5)
spatial/
  tissue_positions_list_with_header.csv  (TESLA)
  tissue_positions_list.csv              (SuperST)
  scalefactors_json.json
  tissue_hires_image.png
  tissue_lowres_image.png
```

Supply H&E and `gene-names.txt` in the input set's configuration. SuperST's
image-size preprocessing is in `methods/prepare_superst_image_size.ipynb`.

XFuse uses `data.h5` generated by `xfuse convert visium`, the study gene list
and an explicit model TOML. Image conversion scale and output scale must match
the actual study settings. Use the finalized study conversion settings.

## Evaluation inputs

Xenium/CosMx: spatially aligned H&E and a transcript table with the gene feature
column and coordinate columns. Set `feature_col`, `x_col_idx` and `y_col_idx`
explicitly if their order differs from `feature_name, x, y`. Evaluation uses the
unmodified HR reference even when the model input is generated with dropout.

Visium HD: the 8 µm ground-truth h5, tissue positions parquet and a fixed range
JSON. Prediction and GT barcodes/coordinates must refer to the same spatial
domain. Use a fresh GT cache when any coordinate setting changes.

XFuse's fixed edge domain must be supplied explicitly. Its transformed/cropped
prediction, image extent and transcript coordinates must agree. Do not pass a
cropped prediction together with unmatched full-slide coordinates and infer
that equal array dimensions establish alignment.

Metric CSVs contain one row per gene and `PCC,SCC,KLD,JSD,SSIM,PSNR,gt_counts`.
Zeros are retained. Missing/non-evaluable values are not imputed. An algorithm
omitted by design is different from an attempted run with no evaluable output.

## Platform notebooks

After the platform-specific coordinate and simulation steps, use
`python -m pipeline.preprocessing.prepare_inputs --help` to package model-ready
files. It checks barcode identities and feature order, retains counts and image
coordinates, and writes the H5, both position-table variants, PNGs and scale
metadata. Provide finalized study gene lists and image/radius settings.

The notebooks are platform-specific workflows, not pre-executed data products.
Set paths, actual physical pixel sizes, selected genes, FOV bounds and approved
crop/registration settings before execution. The archive retains the supplied
scientific simulation functions. Dataset-specific coordinate examples are not
universal defaults for new tissue sections.

- Xenium: provide the image hierarchy, transcript table and Explorer alignment
  matrix. Check OME image levels and physical pixel sizes against the dataset.
- Visium HD: supply the bin-level expression matrix, positions and scale-factor
  metadata. The SVG notebook uses R/HEARTSVG. The matrix notebook calls the
  adjacent helper scripts explicitly using `subprocess.run`. The aggregation
  script optionally accepts `--gene_names` to restrict sparse rows to the existing
  study gene list before aggregation. This avoids materializing the full-gene
  dense matrix and does not select genes using prediction performance.
- CosMx: configure the raw export directories and image-registration session.
  Napari alignment is interactive. Set the density/reference FOV range and
  exported test-region FOV range deliberately; they need not denote the same
  image extent. The supplied crop example must match the approved analysis
  region. Public users without clinical exports can start from authorized,
  already aligned H&E/transcripts, or use the supplied numerical Source Data.

## Source Data and minimum analysis inputs

The manuscript's public data links and access conditions are authoritative.
The archive does not duplicate raw datasets or large Source Data workbooks.

| Analysis | Required data |
| --- | --- |
| Absolute in-sample Table 2 | Fig. 2 and Supplementary Fig. 5 Source Data workbooks |
| HVG/strata/Fig. 3d | Classified gene-level tables, or Supplementary Figs. 6–95 numerical workbook |
| Top-performing genes/Table 3 | Six replicate-averaged method outputs for each of 13 datasets |
| Cross-resolution genes/Table 4 | iSTAR `res_mean.csv` for each of 11 datasets |
| Overlap/Table 5 | Actual selected gene sets and per-dataset gene universe |
| Dropout/Table 6 | Per-run gene metrics or the three seed-level mean values at every registered ratio |
| FOV/adjacent analyses | Gene-level condition metrics with FOV coordinate identities or paired gene identifiers |
| Usability | Actual documentation/response/scaling observations and robustness summaries |

Source Data rows already averaged across repeats cannot recover the original
three runs. Use raw per-run metrics when recomputing computational variability.
The workbook exporter preserves original annotations, including method-specific
boundary labels; it does not resolve any label disagreement by guessing.

## Reference resources for the standalone tools

Dataset similarity requires a reference CSV with the features used by the selected
comparison scheme. FOV similarity uses one reference feature vector per search, generated from a
reference training FOV. Repeat the search for additional reference vectors. The extraction scripts can regenerate these resources
from accessible images and the same checkpoint. Weights, clinical datasets and
reference banks are distributed separately according to their access conditions.
